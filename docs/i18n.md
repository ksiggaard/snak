# Language packs (i18n)

snak's interface is localized via **language packs**: plain JSON files mapping
message keys to translated text. English, German (`de`), French (`fr`), Polish
(`pl`), Spanish (`es`), and Danish (`da`) ship with the app; anyone can add
another language by dropping a single JSON file into a folder — no code
changes, no rebuild.

Pick the language in **Settings → Language**. The default is your system
locale when a pack matches its primary subtag (e.g. `de-AT` → `de`), otherwise
English. Switching applies **live** — no restart — and the choice is stored in
localStorage so startup renders in the right language with no flash.

## Pack format

One file per language, named after its [BCP 47](https://www.rfc-editor.org/rfc/rfc5646)
code: `de.json`, `pt-BR.json`, …

```json
{
  "name": "Deutsch",
  "code": "de",
  "strings": {
    "common.save": "Speichern",
    "sidebar.newChat": "Neuer Chat",
    "composer.noKey": "Kein API-Schlüssel für {provider} hinterlegt. …"
  }
}
```

- `name` — native display name shown in the language selector.
- `code` — the BCP 47 tag; must match what you want selected, and is used as
  the `Intl` locale for date formatting and plural rules.
- `strings` — message-key → translated text.

### Keys, fallback, and placeholders

- **The key list** is the English catalog in
  [`src/lib/i18n.ts`](../src/lib/i18n.ts) (the `en` constant) — the canonical,
  type-checked source of truth. The bundled translations
  ([`src/locales/*.json`](../src/locales)) cover every key and are good
  reference material; `en.json` is intentionally a *thin* pack
  (`"strings": {}`) because English always resolves from the TS catalog.
- **Fallback:** a key your pack doesn't translate renders the **English**
  string — never the raw key. So a partial pack is perfectly usable; coverage
  can grow over time.
- **Placeholders** are `{name}`-style and must be kept verbatim in the
  translation (order may change): `"Delete \"{title}\"?"` →
  `"„{title}“ löschen?"`. Unknown placeholders are left visible.
- **Plurals** are key families selected via `Intl.PluralRules`:
  `search.matches.one` / `search.matches.other` (+ optional `zero`/`two`/
  `few`/`many` where your language needs them — see `pl.json`, which uses
  `one`/`few`/`many`). A missing category falls back to the pack's `.other`,
  then English.

## Installing a user pack

1. Open **Settings → Language → Show languages folder** — this creates and
   prints the app-data `languages/` directory.
2. Drop your `<code>.json` file there.
3. Hit **Refresh** (or reopen the card) and select the language.

Invalid files (malformed JSON, blank `name`, bad `code`, non-string values)
are **skipped** during discovery; validation lives in
`src-tauri/src/commands/languages.rs` (`parse_language_pack`).

A user pack whose `code` matches a bundled language **overrides it per-key**:
its `strings` are merged on top of the bundled ones, so you can refine or fix
individual bundled translations with a small partial pack (and your `name` is
shown in the selector).

## Design notes / decisions

- **Mechanism** — homegrown and dependency-free: a typed English catalog
  (`MessageKey = keyof typeof en`, so `tsc` catches key typos), `t(key,
  params)` with `{name}` interpolation, `tp(base, n)` for plurals, and a small
  Zustand store ([`src/store/i18n.ts`](../src/store/i18n.ts)) holding the
  active locale + strings. Components subscribe through `useT()` /
  `useTp()` / `useIntlLocale()`, which is why switching applies live.
- **Not a plugin category** — there is deliberately no `language` plugin
  category in the T12 plugin host. Packs are declarative, text-only data
  files in a dedicated folder, mirroring the T11 themes-folder loader
  (`list_languages` / `languages_directory` parallel `list_themes` /
  `themes_directory`). Nothing in a pack is ever executed.
- **Persistence** — the selected locale lives in **localStorage** (key
  `locale`), like the theme preference, so it is read synchronously before
  first paint; the SQLite `settings` table is not involved.
- **Dates** — `formatThreadDate` / `relativeTime` in `src/lib/time.ts` stay
  pure and take the locale + label templates as parameters; callers pass the
  active language's values.
- **Coverage boundary** — the main UI surfaces (sidebar, chat, composer,
  canvas, quick overlay, search, usage, settings cards, menus, dialogs) are
  externalized. Deliberately *not* translated: chat/model content, provider
  and font names, the Rust-built native menu and tray labels (File/View/Quit
  — would require pushing strings across the IPC boundary at menu build
  time), the developer-facing crash screen (`ErrorBoundary`), slash-command
  palette descriptions, and deep error strings surfaced from the backend
  (`friendlyError` in `store/threads.ts`).
